## 2026-10-14 — NPU Beat-Level Quality Model (v2) on the RV1103

### Milestone

- An INT8 1D U-Net (364k params, 425 KB `.rknn`) runs on the RV1103 NPU every second: 1.65 ms per 5.12 s window
- Per-beat usable/unusable from a duration-constrained Viterbi over S1/systole/S2/diastole/noise posteriors
- Display shows the status, Q bar, HR, longest usable run, usable beats and coverage; the console prints one line per beat
- Falls back to v1 quality when `/root/segnet.rknn` is missing; v1 gates veto beats

### Implementation Notes

- `src/seg_model.cpp`: zero-copy RKNN.
  - Native input is NC1HWC2 `[1,2,1,256,16]`, written with `pass_through=1` because the runtime cannot convert int8 NHWC.

- `src/seg_quality.cpp`: front-end (STFT + filterbank), streaming scheduler (frames accepted with 1.28 s of future context), Viterbi, beat scoring, `BeatTracker`
- `include/seg_params.h` is GENERATED by `PCGKolect_model/seg/gen_c_tables.py`
- `lib/rknn/`: `rknn_api.h` v2.3.2 (airockchip/rknn-toolkit2) + `librknnmrt.so` pulled from the board (v2.3.2)
- Firmware takes the model path as `argv[1]`, `$PCG_SEG_MODEL`, or the default `/root/segnet.rknn`; new `make upload-model`
- Fixed a v1 robustness bug: `log(0)` on digitally silent windows (`lkurt` now has an epsilon). The v1 parity test still passes.

### Verification

- 5-fold CV on held-out PhysioNet recordings: window AUC 0.964 (v1 0.923), beat-level BA 0.919, S1/S2 F1 0.973/0.963 (see PCGKolect_model/README.md)
- NPU self-test (`npu_selftest`): 99.9 % frame agreement with PyTorch float, cosine 0.9999
- Board replay (`pcg_replay`): 15 held-out recordings, clean + noisy → 507/507 identical beats vs the float reference
- Host parity (`tests/test_seg_parity.py`): features max diff 2e-4; Viterbi, beats and streaming identical
- Live firmware run: NPU loaded, ~6 % CPU

## 2026-10-13 — Display Troubleshooting: Title Cutoff Fix

### Problem

After integrating u8g2-linux, the title "PCGKolect RV1103" was partially cut off at the top of the SSD1306 display. The first line was barely visible or completely missing.

### Root Cause

**u8g2 uses a baseline coordinate system, not top-left.** In u8g2, the `y` parameter in `drawStr(x, y, text)` is the **text baseline** (the imaginary line the text sits on), NOT the top edge of the bounding box.

The original code used:
```cpp
u8g2.drawStr(2, 8, "PCGKolect RV1103");  // baseline at y=8
```

With the `u8g2_font_6x13_tr` font (13 pixels tall), the text extends **upward** from the baseline. So at y=8, the top of the text was at approximately y = 8 - 13 = **-5**, which is off-screen. Only the bottom portion of the letters was visible.

Additionally, the separator line was drawn at y=14, which overlapped with the visible bottom portion of the title text.

### Fix

```cpp
u8g2.drawStr(2, 14, "PCGKolect RV1103");  // baseline at y=14
u8g2.drawHLine(0, 16, 128);                // separator below title
```

With baseline at y=14, the 13px-tall title spans y=1 to y=14 — fully visible. The separator at y=16 sits cleanly below.

All stat row y-coordinates were adjusted accordingly (28, 38, 48, 58 instead of 26, 36, 46, 56).

### u8g2 Y-Coordinate Reference

| Element | Font | Font Height | Baseline Y | Visible Y Range |
|---------|------|-------------|------------|-----------------|
| Title | 6x13_tr | 13px | 14 | 1 – 14 |
| Separator | — | — | — | y=16 |
| Stats | 5x7_tf | 7px | 28, 38, 48, 58 | 21–28, 31–38, 41–48, 51–58 |

### Files Changed
- `src/display.cpp` — adjusted y-coordinates for all text elements

## 2026-10-14 — Link v1: control plane and file service on `/dev/ttyS3`

The ESP32 now multiplexes typed message frames (`A5 5C`, REQ/RSP/EVT/CHUNK)
with the unchanged audio frames on the same duplex UART. Spec:
`PCGKolect_app/docs/PROTOCOL.md`.

* `PcgStream` rewritten as a link endpoint: parses both frame kinds, writes
  whole frames under a TX mutex, tracks audio SEQ and **zero-fills missing
  frames** (≤ 20) so the time axis stays true; every gap/overrun/discontinuity
  is reported with its absolute sample index (`takeGaps()`).
* Baud switching on request (`baud` op) with a 2 s revert if no valid frame
  arrives, plus a link-loss fallback to 460800 after 3 s of silence. The ESP
  negotiates 4 Mbaud after boot (benchmark in the ESP DEVLOG: 334 KB/s
  stream, 128 KB/s request/response, 0 errors in an 18 MB soak).
* `ControlServer`: request queue + worker thread, response cache (last 16 ids)
  so retried requests run once; ops `ping`, `link_stats`, `baud`, `flood`.
* `FileService`: `open`/`read`/`close` with ≤ 4 handles (LRU eviction),
  4 KB `pread` chunks answered as CHUNK frames, virtual `bench` file.
* SHA-256 (`sha256.cpp`) and cJSON 1.7.18 (`lib/cjson`, MIT) vendored.
* stdout is line-buffered (`setvbuf`) — block buffering made `/tmp/rv.log`
  look frozen during debugging.
* Start detached with `setsid`: the firmware's SIGHUP handler overrides
  `nohup`, so it exited when the adb shell closed.
